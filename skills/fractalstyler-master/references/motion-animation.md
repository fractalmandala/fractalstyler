# Motion and Animation

Every duration and easing in Fractalstyler is a token, and every motion class reads one. The CSS below is the definition layer - read it, do not paste it.

## Pick The Pattern First

Four different jobs. Choosing the wrong one is why motion feels either absent or sticky.

| What is happening | Use | Needs JavaScript? |
|:---|:---|:---|
| A control changes state - hover, selected, focus, open | `.spring` plus a `.spring-*` flavour, or a rung (`--motionin1` … `--motionout3`) inside your own rule | No |
| Something appears or disappears | `@starting-style` inside your own rule, keyed to the open state the element already has | No - the rule is the trigger |
| A list or grid animating in on mount | `.anim-fade-in` | No |
| A page or route transition | `.vt-name` and the `html.vt-*` classes | Yes - the helper tags `<html>` with `vt-<type>` |
| Direct manipulation (drag, tilt, pointer follow) | `.motion`, `.tilt` | Yes - JS writes `--mx --my --ms --mr --mo`, `--rx --ry` |

Two more, for feel rather than arrival: `.lift` (hover raises the surface) and `.press` (active pushes it in). They replace the `transition` shorthand, so they do not compose with `.spring` on the same element - pick one.

## Timing Vocabulary

`--speed0` … `--speed3` are 50 / 90 / 140 / 220ms, and each is paired with an *in* or *out* easing into a composed channel: `--motionin1` … `--motionout3`. Enter with the out-easing, leave with the in-easing - the names describe the curve family, and `transout*` decelerates, which is what an arriving element needs. The `.spring-*` set is separate: `linear()` easings with their own settle times, for anything that should overshoot or land physically. The current spring is `--spring` / `--spring-ms`; a `.spring-*` class re-points it for the element and its subtree.

## Reduced Motion

The real lever is `--motion-scale`. It is `1` by default and `0` under `@media (prefers-reduced-motion: reduce)` in `configurations.css`; nearly every duration multiplies by it, so `0` collapses them. There is no `[data-motion]` rule anywhere in the layers - `data-motion="off"`, `"calm"` and `"playful"` are inert, and reduced motion is the media query, not an attribute.

Two limits of this snapshot to work around rather than rely on:

- `.anim-fade-out` has no `both` fill, so the element returns to visible when the animation ends. Hiding something permanently is a class or unmount decision, not a fade-out.
- The reduced-motion block in `motion-animation.css` also names `.anim-in`, `.anim-ping`, `.anim-blink`, `.anim-shimmer`, `.anim-wave`, `.anim-stretch` and `.anim-slide`. None of those seven is defined elsewhere in the stylesheet, so the registry lists them with `animation: none` as their only declaration. The four that exist are `.anim-spin`, `.anim-pulse`, `.anim-fade-in` and `.anim-fade-out`; trust the stylesheet for both lists.

## Verifying Motion

1. Load the page with reduced motion forced and confirm every region is still visible and every dialog still opens and closes.
2. Run again with reduced motion off - every duration is multiplied by `--motion-scale`, so a "stuck" transition is often an unset `--spring-ms`.
3. For each `@starting-style` entrance, check it actually applies on the target browser; where it does not, the element appears without its entrance, which is acceptable - but confirm it is not left invisible.
4. Watch for two owners of the same property on one element: `.motion` writes `translate`, `scale`, `rotate` and `opacity`; `.tilt` writes `transform`; `.press` writes `scale`.
